# TrayDrop 0.1.0

The first Windows-first pre-release of TrayDrop: two-way file transfers over trusted local Wi-Fi, with a native tray panel and a browser client for phones.

## Download and run

1. Download **TrayDrop-0.1.0-win-x64.zip** from this release.
2. Extract it and open the **TrayDrop** folder.
3. Run **TrayDrop.exe** as a normal user.
4. Click the tray icon, choose **Connect a device**, and scan the QR code from a phone on the same trusted Wi-Fi.

The Windows x64 build is self-contained and does not require a separate .NET installation. The portable ZIP includes a how-to-use guide, the MIT project license, and dependency licenses/notices.

Download **SHA256SUMS.txt** to compare the archive or extracted executable with the published SHA-256 values:

```powershell
Get-FileHash -LiteralPath .\TrayDrop-0.1.0-win-x64.zip -Algorithm SHA256
```

## Features

- Native Windows tray icon and an always-on-top lower-right drop panel.
- QR/private-link pairing with phones, tablets, and other browsers.
- Multiple paired devices, editable names, and device-specific outgoing shares.
- Drag/drop or choose files on Windows, then download them from the phone page.
- Browser uploads with progress, cancellation, and zero-byte file support.
- Received files default to the Windows Downloads known folder.
- A remembered custom destination and a reset-to-Downloads option.
- Streaming uploads, byte-range downloads, validated filenames, and no-overwrite saves.
- Revocable shares, close-to-tray behavior, and local diagnostic logs.
- Detailed usage instructions, 15 screenshots, architecture diagrams, and API documentation.

## Verification

- 47 passing regression cases covering transfer state, filenames, uploads, settings, actual HTTP requests, and native Windows drag events.
- Documentation demo verified a byte-exact browser download, a 256 KiB upload, and an empty upload.
- The release excludes debugging-symbol files and includes the relevant dependency notices.

This is not a physical-phone compatibility certification, throughput benchmark, or security certification.

## Important security notice

**HTTP traffic is unencrypted. Use trusted local networks only.** Allow the executable through Windows Firewall on **Private networks only**. Do not expose its port to the internet or enable router port forwarding. Keep live pairing invitations private.

The executable is unsigned and may trigger Windows reputation warnings. Inspect the release origin, source, and checksum; do not disable system security broadly.

## Known limitations

- Windows x64 release only; no native Android/iOS app or macOS/Linux desktop release.
- Browser devices appear after pairing, not through automatic network-wide discovery.
- Individual files only; no folder transfers or resumable uploads.
- No automatic startup, installer, code-signing pipeline, or automatic updates.
- Pairing and outgoing links reset when the app restarts; completed received files stay on disk.
- No encrypted transport, explicit desktop approval for every new pairing, or runtime cryptographic transfer checksums.
